# Island — Pixel 6a 用 Dynamic Island

iPhone の Dynamic Island を、Pixel 6a のパンチホールカメラの位置に再現するアプリ。
音楽の再生・停止・曲送り・シーク、通話、タイマー、ストップウォッチ、アラーム、ナビ、
Android 16 の Live Updates、充電・電池残量低下・消音・おやすみモード・イヤホン・ロック解除の知らせを扱う。
動きと見た目は iOS 26 に合わせている（下の「Apple の見本との一致」）。

## 入れる

```
./deploy.sh            # リリース版をビルドして入れ、設定画面を開く
```

PC が無ければ、GitHub Actions がビルドした APK を端末のブラウザで落として入れる（main に push するたびに作り直す）:
<https://github.com/freudelaufet358358-a11y/AndroIsland/releases/latest/download/Island.apk>
（過去の版は [Releases](https://github.com/freudelaufet358358-a11y/AndroIsland/releases)。初回は「提供元不明のアプリ」の許可が要る）

GitHub Actions の APK を前の版に**上書きで**入れるには、署名の鍵を Secrets に入れておく
（リポジトリは公開なので、鍵はリポジトリに置かない）。手元の debug 鍵を入れれば、`./deploy.sh` で入れたものにも上書きできる。

```
base64 -w0 ~/.android/debug.keystore    # macOS は base64 -i ~/.android/debug.keystore
```

出てきた文字列を GitHub の Settings → Secrets and variables → Actions → New repository secret に
`SIGNING_KEYSTORE_BASE64` という名前で入れる（debug 鍵以外なら `SIGNING_STORE_PASSWORD`・`SIGNING_KEY_ALIAS`・`SIGNING_KEY_PASSWORD` も）。
入れていない間は毎回違う鍵で署名されるので、新しい APK はアンインストールしてから入れ直すことになる。

初回だけ端末で次の 2 つを許可する（アプリのセットアップ画面にボタンがある）。

1. **アクセシビリティ** → Island をオン（島を画面の最上部に描くため）
2. **通知へのアクセス** → Island をオン（音楽・通話・タイマー・ナビを読むため）

アクセシビリティのスイッチが灰色で押せないとき（Android 13 以降のサイドロード制限）は、
アプリ情報の右上 ⋮ →「制限付き設定を許可」してから戻る。
Bluetooth（イヤホン名と電池）・通知（内蔵タイマーの終了）・マイク（音楽の波形を実際の音に合わせる）は画面の「許可」から。

電池残量低下の表示のタップで **バッテリー セーバーをその場で入れ・切り** したいときは、PC から一度だけ次を実行する
（しなければ、タップで設定の「バッテリー セーバー」画面が開く）。

```
adb shell pm grant dev.ryunosuke.island android.permission.WRITE_SECURE_SETTINGS
```

### Shizuku（なくても使える）

[Shizuku](https://shizuku.rikka.app/) が動いていれば、アプリが adb shell と同じ権限でシステムを呼べるので、次のことができる。

- **許可をまとめて付ける。** セットアップ画面の Shizuku の行の「まとめて許可」で、アクセシビリティ・通知へのアクセス・
  Bluetooth・通知・マイク・省電力の切り替え（WRITE_SECURE_SETTINGS）を PC なしで付ける。「制限付き設定を許可」の手順も要らない。
  付けたものは端末の設定として残るので、あとで Shizuku が止まっても消えない
- **省電力を島から直接入れ・切りする。** 設定画面やクイック設定で手動で入れた省電力も、島のボタンで切れる。
  スケジュールには触らない（下の「省電力はシステムの『スケジュール』で入れる」の回り道が要らない）
- **Recents で払ったアプリの音楽をすぐ消す。** 一時停止してから払ったものも、60 秒の猶予を待たずに消える
- **（root で起動したときだけ）ステータスバーの時計とアイコンを島の外に出す。** 下の「ステータスバーを島の外に寄せる」

root なしの Shizuku は端末を再起動すると止まる（Shizuku のアプリからワイヤレスデバッグで起動し直す）。
止まっている間の省電力と Recents は、今までのやり方（スケジュール・Recents を開いている間に止まったら消す）に戻る。
Magisk などで root を取っていれば、Shizuku のアプリで root で起動でき、再起動のたびに起動し直す手間もなくなる。

### ステータスバーを島の外に寄せる（root）

設定の **ステータスバー（root）→ 時計とアイコンを島の外に出す** をオンにすると、ステータスバーの真ん中を島の幅だけ空けて、
時計と通知アイコンを島の左、電池・Wi-Fi などを島の右に寄せる（島の下に隠れなくなる）。root で起動した Shizuku が要る。

- 空ける幅は **自動** なら、ふだん出ているコンパクト（音楽などの、左右に絵を置いた形）がちょうど入り、
  島の端から少し（0.19H、約 7dp）離れる幅。島の幅（「待機時の幅」「広がったときの幅」）を変えると空きも合わせて変わる
  （待機時の幅 47dp なら 136dp、62dp なら 151dp）。2 つ同時の右に離れた丸や、
  タイマーの残り時間のような文字の多いコンパクトは、右のアイコンに少し被る。被らせたくなければ **空ける幅** のスライダーで広げるか、
  「広がったときの幅」を決めて、どのコンパクトも同じ幅にする。展開した島はこれまでどおり覆う
- **左に時計と通知アイコン 2 つ、右に 5G・アンテナ・電池がいつも入るように、空けすぎない**（Pixel 6a の既定の文字サイズで 159dp まで。
  スライダーの右端がそこ）。空けすぎると、システムは入りきらないアイコンを「•」にまとめてしまう。
  3 つ目からの通知アイコンや、ほかのシステムアイコン（Wi-Fi・Bluetooth など）は「•」にまとまるが、その「•」の場所も残してある
  （残さないと、システムは 2 つ目の通知アイコンや 5G とアンテナまで「•」にしてしまう）。文字サイズを大きくすると、アイコンも大きくなるので狭くなる。
  コンパクトの方が広いとき（既定の大きさの島は約 206dp）はアイコンの場所を残すので、コンパクトが出ている間は内側のアイコンに被る
  （設定画面にはみ出す幅が出る。「待機時の幅」を狭めると収まる）
- 切り替えたり幅を変えたりすると、システムの設定を差し替えるので **開いているアプリの画面が一度作り直される**
  （壁紙の色を変えたときと同じ）。なので島の今の幅に合わせて動かすことはできず、いつも同じ幅を空けておく
- **ロック画面のステータスバーは、次に画面を消したときに合わせる。** Android 16 の SystemUI は、ロック画面のステータスバーを
  カメラ穴に合わせて並べるのを最初の 1 回しかしないので、幅を変えてもロック画面だけ古い幅のまま残る
  （空きが広すぎて、右のアイコンが「•」にまとめられる）。そこで幅を変えたら、画面が消えている間に root で SystemUI を再起動して並べ直させる
  （通話中は見送る。端末を再起動しても直る）
- 差し替えは端末の設定として残る（再起動しても、Shizuku が止まっても効いたまま）。**アンインストールする前にスイッチを切る**。
  切らずに消したときは、入れ直して Shizuku の使用を許可すると元に戻る（または PC から
  `adb shell cmd overlay disable com.android.shell:IslandStatusBar`）
- カメラ穴の大きさとして他のアプリにも伝わる。縦向きのアプリの上端の余白は変わらない。横向きでは穴が左右の端に来るので、
  全画面のゲームなどで端の避ける範囲が縦に長くなることがある
- 時計を真ん中に置く設定（カスタム ROM の機能）のときは、時計は動かない

ビルド環境は [TOOLCHAIN.md](TOOLCHAIN.md)。

## できること

| iPhone の機能 | コンパクト | 長押しで展開 | 取り方 |
|---|---|---|---|
| 再生中の音楽・動画 | ジャケット ／ ジャケット色の波形（実際の音。棒ごとに周波数が決まっていて、一番左は 30〜80Hz の低音） | 曲名・アーティスト・シークバー・前/再生/次・出力先 | MediaSession（どのアプリでも） |
| 着信 | （自動で展開） | 名前・拒否・応答 | 電話アプリの CallStyle 通知 |
| 通話中 | 緑の受話器と通話時間 ／ 波形 | 名前・時間・スピーカー等・終了 | 同上（LINE 等の VoIP も） |
| タイマー | 残量リング ／ 残り時間 | 残り時間・一時停止・キャンセル | Google 時計の通知 ＋ 内蔵タイマー |
| ストップウォッチ | アイコン ／ 経過時間(1/100秒) | 経過時間・ラップ・一時停止・リセット | Google 時計の通知 ＋ 内蔵ストップウォッチ |
| アラーム鳴動 | （自動で展開） | スヌーズ・停止 | 時計アプリの全画面通知 |
| マップのナビ | 曲がる矢印 ／ 距離 | 距離・案内・到着予定 | category=navigation の通知と、Google マップの案内中の通知（カテゴリなし。下の「作り」） |
| その他のライブアクティビティ | アイコン ／ 短文・進捗リング・時間 | タイトル・本文・進捗バー・ボタン | Android 16 Live Updates、進捗や時計を持つ進行中の通知 |
| 充電 | 「充電中」／ 緑の % と電池（iOS 26 の電池アイコン） | — | 端末のブロードキャスト |
| 電池残量低下（20%・10%） | （iOS 26 Beta 5 と同じく展開した形で出る）残量と赤い電池のボタン。タップで省電力をオン → 黄色、もう一度でオフ。先に入っていれば最初から黄色 | — | 同上 |
| 消音スイッチ | ベル ／ サイレント・バイブ・着信音 | — | 同上 |
| 集中モード | 月 ／ おやすみ オン・オフ | — | 同上 |
| AirPods の接続 | ヘッドホンと名前 ／ 電池リング | — | Bluetooth（電池は取れる機種のみ） |
| Face ID のロック解除 | 錠が開く | — | ロック解除のブロードキャスト |
| 2 つ同時 | 右に離れた丸（粘ってちぎれる） | 丸を長押しでそちらを展開 | 優先度で主と副を決める |

操作は iPhone と同じ。

- **タップ** → 元のアプリを開く
- **押す** → 島が少し膨らむ（幅 +13%・高さ +15%。iOS 26 と同じ）
- **長押し** → 膨らんだ大きさから展開（触覚フィードバックあり）
- **左右スワイプ** → しまう。しまったあとも待機時の島（カメラの周りの黒い部分）が残り、
  **それをタップするか左右にスワイプすると戻る**（次の曲など、内容が変わったときも戻る）。しまったものが終わると島も消える
- **下へスワイプ** → 通知シェードを開く（島がステータスバーに被さっている所からでも引き下ろせる）
- **展開中に外側をタップ / 上スワイプ / 8 秒放置** → 畳む（着信とアラームは放置では畳まない）

待機時の島（設定でオンのとき）も触れる。長押しがステータスバーに素通しされて通知シェードが開くことはない。
音楽は、一時停止して 60 秒（設定で変えられる）たつか、アプリを **最近使ったアプリから払う・強制停止する** と消える。

優先度: 着信 > 通話中 > 鳴っているもの > ナビ > タイマー > ストップウォッチ > 録画など > 音楽 > 進捗もの。

内蔵のストップウォッチとタイマーは、アプリの画面か **クイック設定のタイル**（「ストップウォッチ」「タイマー」）から動かす。
タイマーが終わると、画面が点いていれば島が「終了」を出し、消えていれば全画面で知らせる。

設定画面の **デモ** で、本物の出来事を待たずに全部の見た目と操作を試せる。
**位置と大きさ** のスライダーで、カメラ穴とのずれをその場で直せる（0 = 自動 = iPhone と同じ比率）。
幅は 3 つ別々に決められる。**待機時の幅**（カメラ部分）、**広がったときの幅**（コンパクト。中身は両端に寄る。
待機時の幅より狭くはならず、中身がカメラ穴に被らない幅は残す）、**展開したときの幅**（画面の中央に置く。
音楽の操作ボタンが重ならない 330dp より狭くはならない）。
**振る舞い → 何もないときも島を出す** をオンにすると、iPhone のように待機時の島が常に見える。
**振る舞い → アニメーションの速さ** で島の動きを 0.5〜2.0 倍にできる（1.0 = iOS 26 と同じ）。
**振る舞い → 音楽の波形を実際の音に合わせる** をオフにすると、音を解析しない擬似的な波に戻る（少し軽くなる）。

## 作り

```
overlay/   AccessibilityService と、画面上部に置く 1 枚の透明な窓
source/    通知リスナー（通知 → 活動）、MediaSession、端末の出来事、Shizuku（ShizukuShell）
builtin/   内蔵ストップウォッチ・タイマー、QS タイル、鳴動
island/    活動のモデル、優先度と操作状態の調停（IslandArbiter）、ボタンの実行
ui/island/ 島の描画。形は AGSL シェーダ、中身は Compose
```

要点:

- **窓は動かさず、触れる範囲だけを動かす。** 窓は展開時の最大サイズで固定し、描いている島の矩形を
  `AttachedSurfaceControl.setTouchableRegion` に毎フレーム渡す。島の外は下のアプリにそのまま届く。
  窓のリサイズで起きるカクつきがない
- **形は 1 本のシェーダ。** 角丸の本体と右の丸を符号付き距離で表し、smooth-min でつなぐ。
  丸が離れるとき iPhone のように粘って伸びてからちぎれる
- **寸法と動きは Apple の映像から測った。** 下の「Apple の見本との一致」を参照
- **波形は端末の出力音声を自分で FFT する。** `android.media.audiofx.Visualizer`（セッション 0）から 20 回/秒、
  直近 1024 サンプル（21ms）の波形を受け取り、ハン窓をかけて解析する（Visualizer 自身の FFT は窓なしなので、
  150〜250Hz の音が一番低い帯に漏れる）。録音はしない（マイクの使用中表示も出ない）。
  音量 0 などで 1.5 秒無音が続くと擬似的な波に戻る
- **棒ごとの周波数としきい値は固定（`EqLayout`）。** 一般的なイコライザと同じく、コンパクトの 5 本は
  60Hz（30〜80Hz）/ 230Hz（80〜450Hz）/ 910Hz（〜1.8kHz）/ 3.6kHz（〜7kHz）/ 14kHz（〜16kHz）、
  展開時の 6 本は 60 / 150 / 400 / 1k / 2.5k / 8kHz。その帯の強さがしきい値（左から −14 / −19 / −28 / −39 / −51dB）を
  超えた分だけ伸びる。曲や直近の音に合わせた相対評価はしないので、低音が鳴っていなければ一番左は伸びない
  （低音を 110Hz で切った曲・808 の無いビートでは、左の棒の平均 0.00）。
  Visualizer はミキサーのバッファ（約 10ms）ごとに音量を目いっぱいまで引き伸ばすので、dB は「そのときいちばん大きい音」に対する値
  （曲 5 曲と合成したヒップホップのビートで、Visualizer と同じ正規化・8bit を再現して合わせた）
- **省電力はシステムの「スケジュール」で入れる。** アプリからは PowerManager の切り替えを呼べず、
  設定の `low_power` を直接書くとシステムの状態が「オフ」のまま入り、設定画面やクイック設定から切れなくなる。
  そこで「残量が○%で自動オン」を今の残量 + 1% に一時的に合わせてシステムに入れてもらい、切れたら元のスケジュールに戻す
- **Shizuku の呼び出しは 2 通り。** 省電力と許可の付与は、adb で打つのと同じコマンド（`cmd power set-mode`・`pm grant`・
  `cmd notification allow_listener`・`settings put secure`）を Shizuku 側で動かす（隠し API に頼らないので Android の版に左右されにくい）。
  最近のタスクの一覧だけは、shell の権限で `IActivityTaskManager#getRecentTasks` を呼ぶ（隠し API の制限は HiddenApiBypass で外す）。
  Recents を開いたときの一覧と、開いている間 0.4 秒ごと（と閉じて 1.5 秒）に取り直した一覧を比べ、消えたタスクのアプリを払われたとみなす。
  Shizuku の `newProcess` は API 13 で非公開になったのでリフレクションで呼ぶ（`proguard-rules.pro` で残している）
- **ステータスバーの空きは、カメラ穴の外接矩形の設定値を差し替えて作る（`StatusBarGap`）。** ステータスバーは
  `config_mainBuiltInDisplayCutoutRectApproximation`（Pixel 6a は 480〜625px × 132px）の幅だけ真ん中を空けて時計とアイコンを並べるので、
  この値を島が入る幅の矩形（高さは同じ）にする fabricated overlay を `cmd overlay fabricate` で作り、`cmd overlay enable` で有効にする。
  fabricate は root でしかできない（shell は OverlayManagerService が断る）。穴の形（`config_mainBuiltInDisplayCutout`）は変えないので、
  穴の縁取りと島の位置は変わらない。効いたかは端末が報告するカメラ穴の上端の矩形（`Display.getCutout()`）で確かめ、
  10 秒たっても変わらなければ overlay を切って諦める（同じ中身では、スイッチを入れ直すまで試さない）。
  矩形が画面の端に届くとシステムが「角にある穴」とみなして真ん中を空けなくなるので、両脇に画面幅の 1/8 ずつは残す。
  また、両脇には時計・通知アイコン 2 つ（3 つ目を「•」にする場所も）と 5G・アンテナ・電池（ほかのアイコンをまとめた「•」の場所も）が入る
  幅を残す（`IslandMetrics.maxStatusBarGapDp`）。寸法は 171dp 空けたときの実機のスクリーンショットで測った（左は端から時計まで 18dp、
  時計 42sp（幅の広い数字の分を足した）、通知アイコンの枠 22sp × 3。右は電池まわりの余白 36dp、電池 26sp、5G とアンテナ 43sp、「•」20sp）。
  空きは画面の中央に置かれるので、左右の広い方（どちらも約 125dp）を両側に残す。
  ロック画面のステータスバー（`KeyguardStatusBarView`）は、並びが「カメラ穴あり」になったあとは `setDisplayCutout` で幅を計算し直さない
  （窓の insets が変わったときだけ計算し直すが、Compose のロック画面ではそれが届かない）。なので overlay を変える前の SystemUI の
  プロセス番号を覚えておき、次に画面が消えたとき（1.5 秒待ってまだ消えていれば）そのプロセスがまだ動いていれば `kill` する
  （SystemUI はすぐに立ち上がり直し、今のカメラ穴で並べ直す）
- **通知の判定は純粋関数。** `NotificationSnapshot` → `NotificationParser` → 活動。JVM のテストで確かめている。
  Google マップの案内中の通知はカテゴリを付けないので、サブテキストが「13 分 · 4.6 km · 11:55 到着」のように「·」で 3 つに分かれて
  いるものをナビとみなす（題名が曲がるまでの距離、本文が案内、大きいアイコンが矢印。形は Gadgetbridge の
  `GoogleMapsNotificationHandler` に合わせた）。距離の数と単位の間は改行しない空白のことがある。矢印が暗い色なら白で塗る。
  Google 時計の独自レイアウト（RemoteViews）は自分のプロセスで展開して中の Chronometer を読む

## 確かめる

```
./gradlew :app:testDebugUnitTest     # 判定・優先度・時計・書式・波形の帯・島の幅
./verify-on-device.sh                # 実機: デモ全種、展開と操作、MediaSession、出力先、通知シェードとの競合、充電、滑らかさ、クラッシュ
tools/record_ios26.sh                # 実機: iOS 26 の見本と同じ 5 つの遷移を録画し、遷移ごとに比べる（今の基準）
tools/record_reference.sh            # 実機: WWDC23 の見本と同じ順番で動かして比べる（寸法の基準。動きは iOS 17 の頃のもの）
./dump-notifications.sh              # 時計・電話・マップの通知を test-data/ に書き出す（判定の合わせ込み用）
                                     # test-data/google-deskclock-*.txt は実機で取った Google 時計の通知
```

実機スクリプトは `adb shell` からだけ送れる受け口（DUMP 権限で保護）で島を操作する。
端末で動いている本物の活動（ストップウォッチなど）は受け口の `refonly on` で一時的に隠して確かめ、終わったら戻す。
`tone <Hz> <秒>` はごく小さなノイズの上に 0.4 秒ごとの音を鳴らし、波形の 5 本の棒の最大と平均をログに出す。
`playraw <名前>` は `/sdcard/Android/data/dev.ryunosuke.island/files/` に置いた生データ（48kHz・モノラル・16bit）を、
試験用の MediaSession を再生中にして鳴らし、終わると 5 本の棒の最大と平均をログに出す（実際の曲で波形を見る。メディアの音量が 0・ミュートだと解析に音が届かない）。
通知の中身をログに出したいときは `adb shell setprop log.tag.IslandListener DEBUG`。
`shizuku` は Shizuku の状態と、Shizuku で読んだ最近のタスクのアプリを `shizuku=Ready uid=2000 tasks=[…]` の 1 行でログに出す
（`verify-on-device.sh` は Shizuku が使えるときだけ、これと「手動で入れた省電力を島で切れる」を確かめる）。
`statusbar` はステータスバーの空きの状態と、端末が今報告しているカメラ穴の上端の矩形を
`statusbar=Applied(widthDp=159) on=true cutout=[331,0][749,132] lockscreenPending=false` のような 1 行でログに出す
（`verify-on-device.sh` は、設定でオンのときだけこれを確かめ、音楽のコンパクトを出した画面を撮る。オン・オフはしない）。

## Apple の見本との一致

### 動き: iOS 26

iOS 26 Beta 4 と Beta 5 の島を並べた映像（YouTube Shorts `5dkH83T_IU8`、30fps）を 1 コマずつ測り
（`test-data/reference-ios26-short.csv`、数値のみ）、遷移ごとに減衰するバネを当てはめた。
iOS 17 の頃（下の WWDC23 の見本）より **1.5〜1.6 倍速く、ほとんど弾まない**（行き過ぎ 1〜2%）。
横に広がるときに高さが膨らむ動きと、高さが遅れて動き出す動きは無くなった。

| 遷移 | 幅（response / 減衰比） | 高さ | 見本 |
|---|---|---|---|
| 待機 → コンパクト | 0.505s / 0.82 | — | Beta 4 |
| 待機・一時表示 → 展開 | 0.485s / 0.84 | 0.51s / 0.81 | Beta 5 の電池残量低下（高さ 2.8H） |
| 展開 → 待機 | 0.465s / 0.87 | 0.45s / 0.92 | Beta 5 |
| コンパクト → 展開 | 0.605s / 0.79 | 0.365s / 0.83 | Beta 4（長押しの膨らみのあと） |
| 展開 → コンパクト | 0.53s / 0.78 | 0.525s / 0.79 | Beta 4 の展開 → 待機 |
| 長押し | 0.2 秒で幅 +13%・高さ +15%（中心を保つ）、そのまま展開へ | | Beta 4 |
| カメラ穴から出る（初回） | 0.45s / 0.86 | 0.34s / 1.0（上に跳ねない） | iPhone には無い動き |

中身は動き出しと同時に強くぼけた状態で現れ、島と一緒に大きくなりながら 0.27 秒でぼけが消える。
Beta 5 の展開時の高さは透かしの帯に下端が隠れるので、帯の中でも島だけが暗い列で測った（外接矩形だと 2.27H で頭打ちになる）。
2 つ同時（右に離れる丸）は iOS 26 の見本が無いので、WWDC23 の値を 0.65 倍の時間にしている。
設定の「アニメーションの速さ」は、すべてのバネと時間を 1 / 速さ 倍にする。

実機での照合（`tools/record_ios26.sh`。島の比率が見本の iPhone と違うので、遷移ごとに始まり → 終わりを 0 → 1 とした進み具合で比べる）:

| 遷移 | 幅 RMS | 高さ RMS |
|---|---|---|
| 待機 → 展開（電池残量低下） | 2.1% | 1.3% |
| 展開 → 待機 | 2.2% | 3.4% |
| 待機 → コンパクト | 0.6% | — |
| コンパクト → 展開 | （見本は長押しで膨らんだ幅から動くので比べない） | 1.9% |
| 展開 → 待機（Beta 4） | （見本は終わりに録画中の点が出るので比べない） | 1.5% |

### 寸法: WWDC23

Apple の WWDC23「Design dynamic Live Activities」（wwdc2023-10194）11:10 からの島の見本を 1 フレームずつ測り
（`test-data/reference-wwdc23-10194.csv`、数値のみ）、寸法を合わせた。

寸法（島の高さ H = 画面幅の 9.5%。iPhone の 37.33pt / 393pt と同じ比率）:

| | 値 | 出どころ |
|---|---|---|
| 待機時の島（カメラ部分） | 3.375H × H | 映像 336×99px |
| コンパクト | 中身はカメラ部分の外、端から 0.4H | HIG の寸法図 |
| 展開 | 左右の余白 0.265H、上端はコンパクトと同じ、角は超楕円（指数 3.2、1.634H）。カメラの横にはアイコンや短い値だけを置き、文字はカメラ穴の下端 + 4dp より下から始める（下の注） | 映像。角は円弧だと誤差が 3 倍 |
| 2 つ同時 | 主は右端をカメラ部分にそろえて左へ伸びる。右の島は 1.2H × H、隙間 0.19H | 映像（中身なしは左へ 0.6H、HIG は 0.9H） |
| 電池残量低下（iOS 26） | 高さ 2.8H。ボタン 2.33H × 1.53H（右から 0.78H）、文字は左から 0.91H | Beta 5 の映像 |

展開したときの文字とカメラ穴: iPhone の展開表示（leading・trailing はカメラの横、center・bottom はカメラの下）と同じく、
文字がカメラ穴の上を通らないようにしている（通ると、その部分が欠けて読めない）。ダウンロードなどの進行中のものは、
カメラの横の行に左にアプリのアイコン・右に短い値だけを置き、題名と本文はその下の行から書く。
音楽は曲名が流れるので、曲名と歌手名の行だけ穴の下端より下に下げる（ジャケットと波形の位置は変えない。島は 3dp ほど高くなる）。
通話・時計・アラームの、カメラの横の高さにある小さな文字（「着信」「タイマー」など）は、長いときに穴の手前で「…」にする。

録画は `screenrecord --size 720x1600`（全解像度だとエンコーダがフレームを落とす）、ステータスバーを隠した明るい画面で撮る
（島に接する通知アイコンで縁の位置がずれるため）。screenrecord は画面が変わったときだけコマを出すので、
コマの間は直前の値のまま扱う（線形補間すると止まっている間の値がずれる）。縮めた録画は右端に 1px の暗い線が出るので端は見ない。

## 実機で確かめたこと（2026-09-24、Pixel 6a / Evolution X 11.11 / Android 16）

`./verify-on-device.sh` が全部通る状態。自動で確かめているのは次のとおり。

- デモ 9 種の表示と 2 つ同時の分割、一時表示 6 種（電池残量低下は展開した形）
- 左右スワイプでしまうと待機時の島が残り、タップで戻る。しまったものが終わると島も消える
- 本物の MediaSession での取得、長押しで展開、再生/停止・次の曲・シークの各ボタン、
  出力先ボタンでシステムの「メディア出力」ダイアログが開く、外側タップで畳む
- 何も出ていないときは触れる範囲が空（`touchable region=SkRegion()`）で、下のアプリにそのまま触れる
- 待機時の島は触れて、長押ししても通知シェードが開かない。島から下へ引くと通知シェードが開く
- 全画面アプリ・通知シェードで隠れて、戻ると出る
- おやすみモードと充電の、本物のブロードキャストでの一時表示
- 電池残量低下の表示のボタンで省電力が入り、もう一度で切れる。島で入れた省電力を設定のスイッチ（`cmd power set-mode 0`）で切れる。
  どちらもスケジュールが元に戻る（残量 15% の放電中を `dumpsys battery` で模擬）
- 展開・収縮の繰り返しでジャンク 0.5〜0.9%。何も出ていないときは描画 0、音楽の再生中は波形を 30fps で描く
  （音の解析を含めて 1 コアの約 20%。解析なしでは約 17%）

受け口やスクリプトで確かめたもの:
- 初回の表示（カメラ穴から出る）で上端が止まる位置より上に行かない
- 長押しで幅 +12.8%・高さ +14.7% 膨らみ、そこから途切れずに展開する
- 音の解析: 実機で Visualizer から音が届き、マイクの使用記録（AppOps）は付かない。
  棒の割り当ては JVM のテストで確かめている（55Hz は一番左、160〜220Hz は 2 本目で一番左は伸びない、1k / 3.6k / 10kHz はそれぞれ 3〜5 本目）
- 実際の曲（アプリ専用フォルダから鳴らした 14 秒、音量 1/25）で、波形の棒がそろわずに 1 本ずつ違う高さで動く
  （相対評価だった頃の確認。周波数を固定した今の作りは、JVM のテストで Visualizer の正規化を再現して確かめている）
- 省電力: 島で入れる → 設定画面のスイッチで切る → 設定画面で入れ直す・切る、が全部効く。
  充電をつなぐと切れてスケジュールが戻り、抜いても入り直さない。先に手動で入っていたら表示は最初から黄色
- Recents を開いている間と閉じた直後だけ「開いている」と判定する（閉じるときの PANE_DISAPPEARED を見る）
- YouTube Music を強制停止・Recents から払うとセッションが消えて島も消える。
  Apple Music は払っても一時停止するだけでセッションが残る（→ Recents を開いている間に止まった再生は消す）

手で確かめたもの:
- Google 時計のタイマー（表示が時計アプリと秒単位で一致、島からの一時停止とリセット）
- Google 時計のストップウォッチ（1/100 秒表示、島からのラップ・一時停止・リセット）。
  時計アプリは一時停止中の通知を秒までの文字にするので、そのときは島も秒までで出す
- 内蔵ストップウォッチ・タイマー（終了で鳴って自動で展開、島の停止ボタンで止まる）
- 島のタップで元のアプリ（時計）が開く、左右スワイプでしまえる
- 横向きで隠れ、縦に戻すと出る

まだ確かめていないもの（人の操作が要る）: 本物の着信・通話、音楽アプリ、イヤホンの接続、生体認証でのロック解除、
着信音モードの切り替え、マップのナビ。
マップのナビは、前は `category=navigation` の通知しか見ておらず、実機の Google マップでは島に何も出なかった（2026-09-29、PiP で案内中）。
カテゴリの無い Google マップの通知を読むようにしたが、まだ実機で確かめていない。

Shizuku の対応（2026-09-27 に追加）はまだ実機で動かしていない。Android SDK を取れない環境で書いたので、
Compose 以外のソースを API 37 のフレームワーク（Robolectric の android-all）に対して型チェックしただけ。
実機では `./verify-on-device.sh` の「Shizuku」の段と、次を手で確かめる:
「まとめて許可」で全部の行が緑になる、音楽を一時停止してから Recents で払うとすぐ消える。

ステータスバーの空き（2026-09-28 に追加）は、実機（root の Shizuku）のスクリーンショットで、ホーム画面のステータスバーの
時計とアイコンが島の外に寄ることを確かめた。そのとき、ロック画面だけが最初に空けた幅のまま残る（右のアイコンが「•」にまとまる）ことが分かり、
画面が消えたときに SystemUI を再起動して並べ直すようにした（これはまだ実機で確かめていない）。
使っている仕組み（root の `cmd overlay fabricate`、カメラ穴の矩形の読み方、ステータスバーが矩形の幅だけ空けること、
ロック画面のステータスバーが幅を計算し直さないこと）は LineageOS 23.0（Android 16）のソースと Pixel 6a の端末設定で確かめ、
幅の計算と設定値の書き方は JVM のテストで確かめた。実機では次を確かめる: 幅を変えたあと一度画面を消して点けると、
ロック画面のステータスバーもホーム画面と同じ幅で並ぶ、`verify-on-device.sh` の「ステータスバーの空き」の段が通る、
スイッチを切ると（画面を一度消したあと）ロック画面も元の並びに戻る。
空けられる幅の上限（2026-09-29 に追加）は、171dp 空けたときのスクリーンショットのアイコンの位置から決め、JVM のテストで
その位置に対して確かめた（通知アイコンが 3 つ並んだ画面。「•」の場所の大きさと、並びきらないときにシステムが「•」の場所を先に取ることは
Android のソースの読みで、実機ではまだ確かめていない）。実機では、上限（159dp）で通知が 3 つ以上・Wi-Fi や Bluetooth のアイコンも出ているとき、
通知アイコン 2 つと「•」、「•」と 5G・アンテナ・電池が出ることを確かめる。

## できないこと（Android の制約）

- 島が横に広がると、その下にあるステータスバーのアイコンは隠れる（root なしではアイコンをずらせない。
  root で起動した Shizuku があれば、上の「ステータスバーを島の外に寄せる」で外に出せる。展開したときは隠れる）。
  iPhone と同じ比率（カメラ部分 3.375H）にしているので、コンパクトは画面幅の半分ほどになる
  （設定の「待機時の幅」「広がったときの幅」で狭められる）
- 着信時は Android 標準の着信バナーの上に島が重なる。操作は島からできる
- 通話中のミュート・スピーカーは、電話アプリの通知にそのボタンがあるときだけ出る
- 出力先ボタンは AirPlay ではなく Android の「メディア出力」ダイアログ（通知シェードの音楽の出力ボタンと同じもの）を開く
- 一時停止してから Recents で払った音楽アプリは、システムから見て何も変わらないので、一時停止後の猶予（60 秒）まで残る
  （Shizuku が動いていれば、最近のタスクの一覧から払われたと分かるのですぐ消える）
- 出力音声が無音のとき（音量 0 で解析に音が届かない場合など）は、波形は擬似的な波になる
- 省電力をアプリから入れ・切りするには adb での許可か Shizuku が要る（普通のアプリには切り替える権限がない）。充電中はオンにできない
- 島ではなく設定画面やクイック設定で手動で入れた省電力は、Shizuku が無いとアプリからは切れない（島のボタンは設定画面を開く）
- Shizuku なしで島から入れている間は、設定の「スケジュールの設定」に「残量 ○% でオン」が出る（切れると元に戻る）
- イヤホンの電池残量は機種の組み合わせによって取れない
- フォントは SF Pro ではなく端末の標準フォント（SF Pro は再配布できない）
